## 需求

1. 我想做一个应用，主要功能是，在日历上新建各种事项，然后日历上会有展示，然后根据事项的内容，自动生成图表
2. 用 vite react-ts 的模板生成项目，Tailwind shadcn，如果后面需要什么依赖酌情下载就好
3. 记得用 frontend-design

## 描述

分成四大部分，一步一步实现

### 日历

1. 样式是个大日历，首屏独占 `100dvh`；图表 section 接在日历下方，页面整体纵向滚动。
2. 顶部布局：
   1. `‹ 年 月 ›` 和「回到今日」统一居中；上/下月分列年月两侧。
   2. 模板按钮固定在最右边。
   3. 图表不放在 header，靠页面向下滚动进入。
   4. 当前不在本月时，「回到今日」按钮高亮；已经在本月时弱化/禁用。
   5. 手机端年份月份缩小，上/下月、「回到今日」、模板退化为图标。
3. 日历头部从周日到周六，每天一个块。
4. 日期单独一行，日期数字固定在右上角；事项显示在日期行下面，日期与事项之间保留和底部 padding 平衡的间距。
5. 每个月显示的日要往前推一个星期 + N 天，N 是为了向前补全到周日、向后补全到周六。
   1. 每月固定 6 行，保证不同月份格子大小一致；自然不足 6 行时向后补一周。
   2. 非本月的日，日期文字颜色淡一些。
6. 当前日子的区分不能太突兀：
   1. 去掉“今天”文字。
   2. 浅靛蓝底 + 靛蓝日期徽章。
   3. 被选中时用浅橙底 + 橙色描边，但保留靛蓝日期徽章。
7. 选择与操作：
   1. 双击某个块打开编辑弹窗。
   2. Shift 区间选择；Windows/Linux 用 Ctrl、macOS 用 ⌘ 逐个加选/取消；鼠标拖动连续选择。
   3. 再点一次已选中的日期取消选中；点击日历以外区域清空选择。
   4. 在任何一个选中的日期右键：编辑、清空；清空需要二次确认。
   5. 选中块用特殊 border 颜色区分。
   6. 月历中每天已有的事项要展示出来。
      1. 日期行左上角显示 `+N`，右上角显示日期。
      2. PC 两列、条数动态计算；移动端 1 列最多 5 条；数值模板带单位。
      3. 事项的全局顺序由模板 `sortOrder` 决定；模板弹窗的列表可拖动排序，编辑弹窗内没有拖动排序。
8. 编辑弹窗：
   1. 单条编辑：
      1. 展示当前选中的日期。
      2. 展示当天已有事项，可编辑、可删除。
      3. 选择某个事项模板后，按模板类型输入：`number` 显示 unit 和 value；`text` 输入字符串。
      4. 保存后留在弹窗，方便继续添加/修改当天其他事项。
   2. 多条编辑：
      1. 展示选中的日期；连续日期显示时间段，非连续日期显示实际选中的日期列表。
      2. 选择模板后，逐日展示输入框，每一天可以填不同值；已有值预填。
      3. 支持“统一填充”，便于一周每天都填 1900 这类场景，填完仍可逐日修改。
      4. 空值跳过，不删除；删除在已有事项表里勾选后批量删除。
      5. 想再补充另一个事项（例如饮食已有 1900 kcal，再补每天吃的是什么），切换模板后继续逐日填即可。
      6. 已有事项表支持全选、逐条勾选、批量删除；删除前二次确认。
   3. 弹窗关闭规则：
      1. 点“完成”提交草稿、关闭弹窗，并统一刷新日历和图表。
      2. 点 X 关闭并放弃未提交修改；有改动时先确认。
      3. 点遮罩不关闭；Escape 等同 X，有改动先确认。
      4. 编辑弹窗和模板弹窗都有全局遮罩，不叠加。
      5. 编辑弹窗没有模板时，提供“去新建模板”入口：先关闭编辑弹窗，再打开模板弹窗。

### 模板

1. 事项模板：
   1. 作用：一，在编辑时快速接入固定事项；二，为图表提供数据支撑。
   2. 字段：
      1. `code`：唯一键，创建后可读，避免历史事件失联。
      2. `title`：事项名称。
      3. `kind`：`number` 或 `text`。
      4. `unit`：值的单位，仅 `number` 使用。
      5. `color`：日历事项色点，也用于图表。
      6. `desc`：事项补充描述。
      7. `sortOrder`：全局事项顺序。
   3. 示例：减脂时新增「体重」`number / kg` 和「饮食」`number / kcal`；心情可以用 `text`。
   4. 文本类型不进入数值图表，图表区用 table 或 markdown 展示。
   5. 颜色支持较多预设色块和自定义取色面板；色点需要保证在白色和浅靛蓝底上可见。
   6. `sortOrder` 是全局顺序：模板弹窗左侧列表可拖动排序，影响所有日期的事项展示顺序；模板列表初始按创建顺序，新模板追加到末尾。
   7. 模板字段约束：
      1. 已有事件的模板不允许修改 `kind`。
      2. `code` 创建后只读。
      3. 标题、颜色、单位、描述可修改。
      4. 删除时显示使用条数，确认后级联删除相关事件。
      5. 模板列表显示使用次数。
   8. 模板弹窗：大弹窗，左列表右表单，带预览；左列表可拖动排序；「新建模板」按钮放在左列表底部；新建模板默认标题按 `新事项 N` 递增、颜色随机取明亮预设色；与编辑弹窗不叠加。
   9. 模板校验：标题错误显示在对应输入框下方并标红输入框，预留错误行高度，避免弹窗因报错变高。

### 图表

1. 位置：日历下方，全宽 section，页面滚动进入；header 不放图表按钮。
2. 阶段 5a 已完成框架，5b 实现具体图表渲染：
   1. 图表 section 标题、案例选择、空状态。
   2. 独立的图表模板入口。
3. 阶段 5a 落地口径：
   1. 图表数据独立存 `datas/charts/charts.json`，通过 `GET/PUT /api/charts` 读写。
   2. 图表模板独立管理，绑定单个事项；数值支持折线/柱状/面积，文本支持对照表/分布；指标支持每日、7 日均、30 日均、变化率。
   3. 案例保存日期区间、事项筛选和行/槽位布局；槽位可放图表、块或留空；图表高度 1–4，块高度 1–2。
   4. 块在案例内创建/编辑，支持固定值、最新值、最大值、最小值、累计减重、区间变化、BMI、距离目标；范围支持案例、全部历史、近 N 天。
   5. 原生 HTML5 拖拽移动/复制；移动端槽位单列。
   6. 删除图表模板按去重案例数提示并清空案例中的对应图表；删除事项模板时图表/块软失效。
   7. 图表模板可在案例编辑期间打开管理；草稿保留，删除模板同步清理草稿失效图表。
4. 后续方向：
   1. 时间范围已由案例区间承担，后续可补快捷区间。
   2. 事项多选筛选已接入案例 `eventCodes`。
   3. `text` 类型：日期 × 模板的对照表，方便前后对比；另可提供词频/分布视图。
   4. `number` 类型：展示每日值、单位、颜色、描述，以及 7 日均、30 日均、变化率等指标。
   5. 每个事项模板可以有专属的图表模板；图表模板独立管理，并与事项模板关联。
   6. 图表模板负责展示方式、指标、图表类型、排序等，不塞进事项模板表单。

### 其他

1. 数据持久化：
   1. 前端项目，希望数据落在仓库内 `datas/`，方便换机器时随项目拉取。
   2. 方案：Vite 中间件提供 `GET/PUT /api/calendar` 与 `GET/PUT /api/charts`，分别读写 `datas/calendar/calendar.json`、`datas/charts/charts.json`；dev 与 preview 可用，静态部署降级 localStorage + JSON 导入导出。
   3. 数据结构：

```json
{
  "version": 1,
  "templates": [
    {
      "code": "weight",
      "title": "体重",
      "kind": "number",
      "unit": "kg",
      "color": "#0f766e",
      "desc": "",
      "sortOrder": 0
    }
  ],
  "events": {
    "2026-10-27": {
      "weight": 75.2,
      "mood": "平静"
    }
  },
  "chartTemplates": []
}
```

   4. 每天每个模板最多一条记录，`events[date][code]` 天然保证唯一；日历数据里的 `chartTemplates` 为早期兼容字段，当前不使用。
   5. 事件全局顺序由模板 `sortOrder` 决定，不在每日事件里单独存 order。
   6. 弹窗统一使用 session draft：打开时复制当前数据，所有编辑只改草稿；“完成”时写盘并统一刷新日历/图表；X 放弃草稿。
   7. 图表模板和事项模板分开存储，图表模板通过 `eventCode` 关联事项模板；案例通过 `eventCodes` 筛选图表模板。
